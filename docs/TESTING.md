# Тестирование

## Как запускать

```bash
npm run typecheck   # tsc --noEmit (strict, noUncheckedIndexedAccess)
npm test            # собирает tests/ → dist-tests/ и гоняет node --test
```

Ожидаемый результат: **125 тестов, 0 падений** (12 сьютов).

Тесты пишутся на `node:test` + `node:assert/strict` и собираются esbuild-ом
(`build.mjs --tests`), поэтому импорт из `src/` — настоящий TypeScript,
никаких моков модульной системы. В каждом файле первые два импорта помечены
`@ts-ignore` — `@types/node` не является зависимостью проекта.

## Служебные аудиты (без зависимостей)

```bash
node tools/audit-i18n.mjs
```
Каждый `t("ключ")` в `src/` обязан существовать в `ru.ts`; `en.ts` обязан
покрывать ровно те же ключи (нет ни пропусков, ни мёртвых). Возвращает
ненулевой код при проблеме.

```bash
node tools/audit-imports.mjs
```
Проверяет, что ни один импорт не остаётся неиспользуемым (ловит «мусор после
рефакторинга»).

```bash
node tools/render-vars.mjs
```
Собирает и исполняет entry и сохраняет скомпилированный CSS переменных
(использовался для live-сверки с форумом; в ручном контуре).

## Ручная проверка (smoke)

**Панель управления.** `node tools/serve.mjs` (статика `dist/` на
`localhost:8477`) → открыть `options.html?...`. Консоль будет честно ругаться
`WebExtension API is unavailable` и падать на онбординге — это задокументированное
поведение fallback-слоя, не баг: UI обязан отрисоваться и жить в обычной
странице. После каждой пересборки страницу надо перезагружать с новым
`?v=N` — hash-навигация бандл не перечитывает.

**Форум.** Расширение → `https://forum.rodina-rp.com/`. Проверялось:

* `auditSelectorHealth` (24/26 главная, 9/11 список тем, 11/15 тема) —
  промахи приходятся на шаблоны конкретных страниц (календарь, галерея и т. п.)
  и предусмотрены деградацией;
* сквозной доказательством: до/после вычисленные стили совпадают с токенами
  темы (футер, блоки, кнопки, пост, `--rfs-font-family`, `--rfs-page-bg`).

В фоне проверки использовался `tools/serve.mjs`; перед релизом его нужно
остановить.

## Что НЕ покрыто автотестами (и почему)

* Реальный DOM XenForo — селекторы проверяются реестром и live-аудитом,
  а не jsdom (нет зависимости, поведение важнее снимка).
* Визуальный рендер (canvas-эффекты, стекло) — ручной smoke на форуме.
* Удалённый AI-провайдер — guard-тесты (согласие/HTTPS/ключ), живые
  запросы не выполняются автоматически, чтобы тесты не зависели от сети.
