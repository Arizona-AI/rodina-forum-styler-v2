# AI: что есть, как работает, чего нет

## Принцип честности

В расширении **нет встроенного ИИ**. Есть два провайдера, и интерфейс
всегда показывает, какой реально отработал:

| Провайдер | Что это | Подпись в панели |
| --- | --- | --- |
| `local` | детерминированная эвристика на правилах (слова → палитра, WCAG-анализ) | «Локальная эвристика (без ИИ, офлайн)» — нейтральный индикатор |
| `openai` | вызов OpenAI-совместимого `chat/completions` **вашего** endpoint | предупреждающий индикатор «Удалённый ИИ с вашим ключом» |

Фасад `ai/index.ts` → `runAiTask(task, input)`:

| Задача | local | openai |
| --- | --- | --- |
| `generate` (тема по описанию) | ✓ всегда | ✓ только при выполненном всех guard-условиях; при ошибке — тихий откат на local, панель показывает фактического провайдера |
| `harmonize` (палитра по основному цвету) | ✓ всегда | **никогда** — палитра не покидает браузер |
| `analyze` (проверка контраста) | ✓ всегда | никогда |
| `improve` (план улучшений) | ✓ всегда | никогда |
| `testConnection` | — | ping вашего endpoint |

## Локальная эвристика (`ai/local.ts`)

* `describePrompt` — разбор описания на признаки: тёмная/светлая, ключевые
  слова оттенков (красный/синиый/зелёный/…), «неон», «пастель», «минимал»;
  радиус и «мягкость» по словам («острый», «округлый»).
* `generateThemeFromPrompt` — детерминированная сборка 30 токенов из
  признаков (одинаковый вход → одинаковый выход; покрыто тестом).
* `harmonizeFromBase` — акцент/вторичный/третичный из базового цвета
  (HSL-повороты + подгонка контраста).
* `analyzeContrast` — WCAG-пары (текст/фон, primary/surface и т. д.) →
  список проблем с фактическим контрастом.
* `suggestImprovements` — правит по приоритету: `primary` → `primaryFg` →
  `buttonFg` → `text` → `textMuted`, каждый результат повторно
  проверяется на целевой контраст.

Ни одна из этих функций не выполняет сетевых запросов.

## Удалённый провайдер (`ai/remote.ts`)

Скелет OpenAI-совместимого клиента под **ваш** endpoint и ключ. Вызов
`chat/completions` возможен только когда выполнены **все** условия:

1. `ai.enabled` — AI-инструменты включены в разделе;
2. `ai.provider === "openai"` — выбран удалённый провайдер;
3. `ai.allowRemote` — явное согласие «можно отправлять палитру на endpoint»;
4. endpoint начинается с `https://` (http отклоняется);
5. ключ сохранён в `rfs.aiSecrets`.

При запросе отправляется **только** описание темы и/или токены палитры —
никаких данных форума, настроек или идентифицирующей информации. Ответ:

* таймаут 20 с (`AbortController`);
* `extractJsonObject` вырезает JSON из ответа модели (в т. ч. из ```-блоков);
* `sanitizeTokens` пропускает только валидные цвета/длины — в модель
  нельзя «вшить» CSS/JS, и в панель попадают только проверенные значения;
* любая ошибка → откат на локальную эвристику с честным сообщением.

Ключ (`apiKey`):

* живёт в отдельном ключе `rfs.aiSecrets`;
* не экспортируется, не пишется в логи, не попадает в отчёт отладки;
* поле ввода показывает «сохранён/не сохранён», не сам ключ;
* удаляется очисткой поля + сохранением.

`testConnection` делает минимальный запрос и возвращает
`ConnectionResult { ok, message }` — для диагностики URL/ключа без
расхода генерации.

## Почему это не «ещё один AI-микс»

* Локальный провайдер подписан как эвристика — пользователь не получает
  ложного впечатления о генерации «умом».
* Удалённый требует три осознанных действия (включить → согласиться →
  дать ключ/endpoint), иначе guard возвращает ошибку — тест
  `ai.test.ts` это фиксирует.
* Сетевая активность расширения в целом = ровно один вызов `fetch` в этом
  модуле (проверяется греп-аудитом, см. [SECURITY.md](SECURITY.md)).

## Ограничения (честно)

* Эвристика не понимает свободный текст семантически: «как закат над
  морем» сработает по ключевым словам (природа/оранжевый), но не по
  настроению. Это ограничение правил, не баг.
* Удалённый скелет рассчитан на OpenAI-совместимые API (стантартный
  `/chat/completions`); экзотические провайдеры с другими путями
  не поддерживаются.
* Провайдер не «улучшает существующую тему» на remote — задачи
  `analyze`/`improve`/`harmonize` намеренно локальны, чтобы анализ
  приватности не зависел от сети.
